# DECISIONS

Deviations from CLAUDE.md and notes from the Rule 7 docs check (docs read 2026-10-14:
`for-coding-agents.md`, `search-api/reference.md`, `fetch-api/reference.md`).

## Docs vs CLAUDE.md Section 2
1. Search default rate limit in docs is **30 req/min** (CLAUDE.md planned 5/min from the launch blog). Kept 5/min as the safe default, configurable via `CITEGAP_SEARCH_RPM`.
2. Search has extra params (`pub_year_*`, `publisher`, etc. in results). Not needed; unused.
3. Search `include_domains` / `exclude_domains` are comma-separated strings. Used `include_domains` for the indexation probe.
4. Fetch `highlights` requires `format: "markdown"`, accepts `query`, `max_snippets` (1-20), `max_characters`, `include_full_page_text`. Highlights query must contain the entity/topic words; we build it as `<h1 entity> <target query>`.
5. Fetch `highlights` is computed only for standard web pages (absent on PDFs). Treated as "not available", not "empty".
6. Fetch `include_selectors` / `exclude_selectors` max 20 entries each; invalid CSS returns 422; PDF/CSV targets return `selector_unsupported`.
7. Fetch docs recommend client timeout 150 s (backend 110 s/url, CDN 120 s). Used 150 s.
8. Fetch rate limit is URLs/minute (150 default) rather than requests/minute. Limiter counts URLs.
9. Docs recommend the SDK. Rule 8 in CLAUDE.md says raw httpx for control of backoff/logging. Kept raw httpx.

## Implementation decisions
- **Own robots.txt parser** (longest-match, `*`/`$` wildcards, UA groups) instead of `urllib.robotparser`, which does not implement Google-style wildcards or longest-match precedence. Needed for correct per-bot evidence lines.
- **SSRF guard** resolves DNS and validates every IP before each hop (manual redirects, max 5). The connect step then goes to the validated IP only (Host header + SNI preserved), so there is no resolve/connect gap.
- **SVS rank points:** pos 1 = 35; 2-3 = 30; 4-10 linear 26 -> 14; 11-20 = 8; absent = 0. If a component cannot be measured (e.g. no competitors found) it is excluded and SVS is rescaled to 100 with a visible note.
- **Raw fetch of competitors** (our SSRF-safe GET, not a TinyFish call) is used only to read their JSON-LD / dates, because Fetch strips scripts.
- **Browser API (Phase 6): built as OPT-IN, EXPERIMENTAL, off by default** (`--deep` / UI checkbox, `pip install citegap[deep]`). It yields finding classes Fetch cannot reach (`EXTRACT_INTERACTION_ONLY_CONTENT`, `EXTRACT_CONSENT_OVERLAY`, plus a load screenshot). The analysis is unit-tested with an injected driver, but it has NOT been run against the live Browser API, so the decision gate (>= 1 reproducible finding on >= 2 real demo pages) is not met. Until it is, the submission claims **2 endpoints (Search + Fetch)**; claim 3 only after validating live. If it fails the gate, delete `collect/browser_deep.py`, `analyze/deep.py` and the flags.
- **Bridge for blocked AI bots** targets a virtual symptom `AI_ANSWER_VISIBILITY`, not Google rank (be precise).
- Fixtures in `tests/` only. `examples/` is README-only content generated by `scripts/demo_set.py` from real live audits (needs a key).
- **Search page>0 positions:** docs do not say whether `position` is page-relative. `collect/serp.py` treats page-1 positions that are <= the page-0 result count as relative and adds that offset, so rank 14 stays 14 either way. Verify against a live call.
